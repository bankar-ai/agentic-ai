# AGT-048 — Result Panel Doesn't Show Which Question It's Answering

Status: Backlog
Depends On: None
Category: Bug

## Description

Found 2026-10-05 from live screenshots: looking at a result panel (live or reopened from history,
`AGT-040`), there is no indication anywhere of what question produced it. Confirmed in code --
`DisplayResult` (`components/ResultPanel.tsx`) has no `question` field at all, and `ResultPanel`
never renders one. The project owner's own words: "not able to get which question i am looking
into... so trace for agentic rag should show Question and then whatever right now we are showing
-- that is same tray should be opened and not the different one." A live result and a reopened
history entry currently look like two visually unrelated things partly *because* neither shows
the question -- adding it makes both read as the same consistent format.

## Acceptance Criteria

- [ ] `DisplayResult` gains a `question` field; `ResultPanel` renders it as a heading above the
      verdict badges/answer (e.g. bold, slightly larger than the answer text)
- [ ] Both a live query's result and a reopened history entry (`AGT-040`) show their question this
      way -- same component, same treatment, so switching between "just asked" and "reopened from
      history" doesn't look like two different UI patterns
- [ ] Deployed and visually confirmed: ask a question, confirm it's shown; open a different
      question from history, confirm the panel updates to show *that* question

## Notes

Small, contained fix -- `question` already exists as data (`query` in `QueryPage.tsx`'s
`handleSubmit`, `entry.question` in history) it just never reached `DisplayResult`.
