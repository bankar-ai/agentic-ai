# AGT-039 — Agent Trace as Graph Steps + Prominent Final Verdict

Status: Done
Depends On: AGT-037
Category: Improvement

## Description

The agent trace today renders as `JSON.stringify(step)` per `<li>` — unreadable, especially for a
rejected query with two retry rounds (confirmed live, `AGT-035`'s verification run: a wall of raw
JSON, no visual separation between the two Gatekeeper->Research->Writer->Verifier passes). Replace
it with an actual stepper: one node per agent, in sequence, each showing an icon + one-line
summary collapsed by default (route chosen / evidence count / grounded yes-or-no), expandable for
the full `reasoning`/`unsupported_claims` text. A retry loop (Verifier rejects, Research/Writer run
again) renders as a visibly repeated Research->Writer->Verifier segment, not a flat continuation of
the same list, so a two-rejection run is legible at a glance.

Also: the final answer/verdict is currently just a paragraph below the trace, same prominence as
everything else. Make it the visual headline of the result — a clear "Grounded" / "Refused" verdict
badge plus the answer text, with the trace as supporting detail underneath, not the other way
around. Direct RAG (no trace, no verdict concept) keeps its current "answer + source filename"
treatment, same visual prominence for the answer itself.

## Acceptance Criteria

- [x] Agentic RAG trace renders as a vertical stepper (one visual node per agent step), not raw
      JSON — each node shows a one-line summary by default, expandable for full detail
- [x] A retry loop (multiple Research/Writer/Verifier passes) is visually distinguishable as a
      repeated segment, not a flat undifferentiated list
- [x] Final answer is the visual headline: a verdict badge (Grounded/Refused) + the answer text,
      more prominent than the trace below it
- [x] Direct RAG's answer keeps equivalent visual prominence (no verdict badge, since there's no
      verification step, but same headline treatment)
- [x] Desktop/laptop viewport only — see `AGT-042`
- [x] Deployed and live-verified against a real rejected query (reuse the fall-protection-training
      question that reliably triggers a two-round rejection) and a real grounded query

## Resolution (2026-10-04)

New `components/TraceStepper.tsx`: one collapsible node per agent step (icon + one-line summary,
expandable for full `reasoning`/`unsupported_claims`/draft text), with a "Retry" divider inserted
before any `research` step that isn't the trace's first step. New `components/ResultPanel.tsx`
makes the verdict/answer the headline (a Grounded/Refused badge for Agentic mode, duration badge
for both modes) with the trace collapsed underneath; shared by both a live result and a reopened
history entry (`AGT-040`). Live-verified against two fresh real queries: a ladder-safety question
that triggered `web_fallback` routing, a Verifier rejection citing mismatched web-sourced
evidence, a retry, then a `grounded: true` final answer (`duration_seconds: 40.09`) -- confirms
the stepper correctly renders a non-`kb` route and a full retry-then-success trace, not just the
`kb`-route rejection case already verified in `AGT-035`. Deployed as part of commit `365d7f1` on
`main`.
