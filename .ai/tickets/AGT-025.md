# AGT-025 — Show the User's Own Ingested Documents

Status: In Progress
Depends On: None
Category: Feature

## Description

A user has no way to see what's actually in their knowledge base before asking a question — they
have to guess, or get surprised by a refusal. `enterprise-rag-platform` already exposes
`GET /documents` (ERP-103, returns the caller's successfully ingested documents, paginated,
cookie+CSRF authenticated same as `/retrieval/query`) — this is a proxy of an existing capability,
not new backend work on that platform's side.

## Acceptance Criteria

- [ ] New method on a small `RagPlatformDocumentsClient` (`app/rag_client/documents.py`),
      mirroring `RagPlatformRetrievalClient`'s auth pattern exactly (Cookie + X-CSRF-Token
      headers, refresh-once-on-401/403, `RagPlatformRetrievalError`-style error type)
- [ ] New `GET /documents` on `agentic-ai`'s own API (`app/api/router.py` or a new router),
      requiring the same `Authorization`/`X-RAG-CSRF-Token` headers as `/query`, returning the
      caller's documents (filename, ingested date)
- [ ] Frontend: a documents list visible from the query page (collapsible panel or separate
      section — not a separate login), showing filename + ingested date, with a clear empty-state
      message ("No documents yet — ingest one on enterprise-rag-platform directly") since there is
      no upload capability here (that stays on `enterprise-rag-platform`, out of scope)
- [ ] Tests: client auth/refresh behavior (mocked), endpoint auth requirement
- [ ] Live-verified against the real RAG platform
