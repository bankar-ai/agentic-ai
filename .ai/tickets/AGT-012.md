# AGT-012 — Minor Polish from the Final Review

Status: Backlog
Depends On: None
Category: Lapse

## Description

Small, non-blocking items flagged by the final whole-branch review's fix-wave re-review
(2026-09-30) and genuinely deferred rather than fixed, bundled into one low-priority ticket since
none individually warrants its own:

1. A `ToolError` raised inside the MCP subprocess (e.g. the RAG platform being unreachable from
   *inside* the subprocess call) surfaces to the API caller as `event: error` with the raw
   `ToolError` type name, not a friendlier "knowledge base unavailable" message. Still a clear
   error, not a silent failure — just less legible than it could be.
2. Inline citation markers in the Writer's draft text (e.g. `[some-file.pdf]` written into the
   prose) aren't cross-checked against `cited_evidence` — a Writer could in principle put a
   legitimate item in `cited_evidence` while writing a different, fabricated filename directly
   into the answer text. The Verifier's LLM content-check against real retrieved text would
   normally catch this, but there's no deterministic code-level guard for it the way there is for
   `cited_evidence` itself.
3. `app/mcp_server/server.py`'s `_build_retrieval_client()` opens an `httpx.AsyncClient` that's
   never explicitly closed (same class of issue as `AGT-009`, narrower scope — just this one file).

## Acceptance Criteria

- [ ] Item 1: map `ToolError`/`McpError` from the MCP subprocess to a specific, user-legible error
      event type (e.g. `KnowledgeBaseUnavailable`) in `_research_kb`'s error handling
- [ ] Item 2: decide whether a deterministic code-level cross-check is worth adding, or whether the
      existing LLM content-check is judged sufficient coverage — document the decision either way
- [ ] Item 3: covered by `AGT-009`'s broader client-lifecycle fix if that lands first; otherwise a
      standalone fix here

## Notes

All three are genuinely low-risk; bundle-fix opportunistically rather than scheduling dedicated
work unless one becomes a real problem in practice.
