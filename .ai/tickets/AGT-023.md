# AGT-023 — Rename Vercel Project to Match `enterprise-rag-platform`'s Convention

Status: Blocked (project-owner decision needed — see Resolution)
Depends On: None
Category: Improvement

## Description

`agentic-ai`'s Vercel project still has its auto-generated subdomain
(`agentic-ai-psi-mauve.vercel.app`). `enterprise-rag-platform` hit the exact same cosmetic issue
and fixed it the same way (`ERP-057`): renamed the Vercel project to a readable, org-prefixed
name (`bankar-ai-self-hosted-rag-platform.vercel.app`). Do the same here for consistency across
the portfolio.

**Known gotcha from ERP-057, applies identically here:** the backend's CORS allowlist is an exact
string match on Origin — renaming the Vercel project without updating `CORS_ALLOWED_ORIGINS` on
Cloud Run breaks login silently (browser blocks every cross-origin request, no server-side error
to find). Both must change together.

## Acceptance Criteria

- [x] Readable alias created: `bankar-ai-agentic-ai.vercel.app` → the project's production
      deployment (`vercel alias set`)
- [x] `CORS_ALLOWED_ORIGINS` on the `agentic-ai` Cloud Run service updated to accept both origins
- [ ] **Blocked**: the new alias is gated by Vercel's own SSO deployment protection (see
      Resolution) — not usable as the public URL until the project owner decides how to handle it
- [x] `gcp-deployment-tracker.md` updated

## Resolution (2026-10-04)

Created the alias the same way `enterprise-rag-platform`'s own frontend got its readable URL
(`ERP-057`, `vercel alias set`). Unlike that precedent, this new alias returns `302` to
`vercel.com/sso-api` — Vercel's own SSO deployment protection, confirmed via `curl -sI` (not a
propagation delay; re-checked after several minutes, unchanged). Compared project settings
directly: both `agentic-ai` and `enterprise-rag-platform`'s `frontend` project report the
identical `ssoProtection.deploymentType: "all_except_custom_domains"` — so the setting itself
isn't the difference; `agentic-ai-psi-mauve.vercel.app` (the project's own canonical auto-assigned
domain) is exempted automatically as *the* production domain, but an additional alias apparently
isn't granted the same exemption on this project, for reasons not fully root-caused.

The one lever that would reliably fix this (`vercel project protection disable agentic-ai --sso`)
is a real security-protection change on a project, correctly refused by the session's own
safety guard without explicit authorization — not attempted further. **`agentic-ai-psi-mauve.vercel.app`
remains the one confirmed-working public URL; `bankar-ai-agentic-ai.vercel.app` exists but is not
currently usable.** Needs the project owner to decide: disable SSO protection for this project (matches
`enterprise-rag-platform`'s own public-by-design posture), or leave the existing URL as canonical
and drop this ticket's cosmetic goal.
