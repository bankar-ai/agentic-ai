# AGT-009 — Manage `get_graph()`'s Client Lifecycle

Status: Backlog
Depends On: None
Category: Lapse

## Description

`get_graph()` (`app/api/router.py`) rebuilds the Ollama model, an `httpx.AsyncClient`, the auth
client, and the retrieval client from scratch on every single `POST /query` request — and the
`httpx.AsyncClient` instances it creates (here, in `app/ui/app.py`, and in
`app/mcp_server/server.py`) are never explicitly closed. Flagged as a deferred Minor in the final
whole-branch review (`M-3`) and in `AGT-013`'s Task 13 ledger note. Fine for a low-traffic demo;
genuinely wasteful (a fresh TCP connection and a fresh RAG-platform login per query) for anything
with real concurrent traffic.

## Acceptance Criteria

- [ ] A shared, lazily-constructed (or FastAPI-lifespan-managed) `httpx.AsyncClient` reused across
      requests, properly closed on app shutdown
- [ ] `RagPlatformAuth`'s cached-token benefit actually realized across requests (currently reset
      every request since a fresh instance is built each time, defeating the point of its own
      token-caching design)
- [ ] Same treatment for `app/ui/app.py` and `app/mcp_server/server.py`'s client construction

## Notes

Category is **Lapse**, not Bug — the code works exactly as designed, the design just didn't
account for a high-request-volume case. Low priority unless/until real concurrent traffic is
expected (e.g. before a live interview demo with multiple testers hitting it at once).
