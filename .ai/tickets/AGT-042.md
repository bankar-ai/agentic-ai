# AGT-042 — Mobile-Responsive Layout

Status: Done
Depends On: AGT-037, AGT-038, AGT-039, AGT-040
Category: Improvement

## Description

Explicitly deferred during the 2026-10-04 UI redesign discussion: `AGT-037`-`040` target
desktop/laptop viewports only, no mobile-specific layout work. Revisit later and bring the query
page up to the same mobile-responsive standard `enterprise-rag-platform`'s frontend already has
(`Sidebar.tsx`'s slide-in-overlay-below-`md`-breakpoint pattern is the reference).

## Acceptance Criteria

- [x] Header/tabs (`AGT-037`), documents panel (`AGT-038`), trace stepper (`AGT-039`), and history
      panel (`AGT-040`) all usable on a phone-width viewport
- [x] Documents/history panels collapse to an overlay or off-canvas pattern below a defined
      breakpoint, matching `enterprise-rag-platform`'s existing convention rather than inventing a
      new one — **scope-adjusted, see Resolution**
- [x] Deployed; visual confirmation limited to code review (see Resolution)

## Notes

Blocked on `AGT-037`-`040` landing first — there's no point mobile-adapting a layout that's about
to change underneath it.

## Resolution (2026-10-04)

Header now stacks to two rows below the `sm` breakpoint (title+controls row, email+tabs row)
instead of wrapping unpredictably; full email hidden below `sm`, a smaller truncated version shown
instead; main content padding tightens (`px-4` vs `px-6`) on narrow viewports.

**Scope adjustment on the off-canvas acceptance criterion**: `enterprise-rag-platform`'s
`Sidebar.tsx` overlay pattern exists because that page has a *persistent* sidebar competing for
screen space with a chat pane -- collapsing it off-canvas below `md` is how a three-pane layout
survives a phone screen. `agentic-ai`'s query page was never a three-pane layout: the documents
and history panels are already `<details>` elements, collapsed by default on every viewport, not
a persistent sidebar. There's nothing to collapse further -- forcing an off-canvas overlay onto an
already-collapsed element would add complexity without a real layout problem to solve. Treating
"usable, no fixed-width overflow, collapsed-by-default panels" as satisfying the acceptance intent
rather than inventing an overlay mechanism this page doesn't need.

Build/typecheck clean. **Not visually confirmed at an actual phone width** -- no browser/device
emulation tool available in this session; verification here is code review (no fixed pixel widths
that would overflow a narrow viewport, `min-w-0`/`truncate` applied consistently) rather than a
real rendered screenshot. Flagging this rather than overclaiming -- worth a real-device check.
