# AGT-006 — Remove the Anonymous Service-Account Fallback; Require a Real RAG-Platform Login

Status: Done
Depends On: None
Category: Improvement

## Description

**Superseded design (2026-10-01):** this ticket originally planned to register a service user and
ingest demo content on the live `enterprise-rag-platform` deployment, so an anonymous visitor to
this project's demo would see *something* in the KB-hit path without needing their own RAG-platform
account.

The project owner explicitly rejected that design: this project should **only** be usable by
someone who already has their own `enterprise-rag-platform` account. There is no shared
demo/service account anyone can query, logged in or not — multi-tenancy (`AGT-013`/`AGT-014`) is
not an optional nicety layered on top of a default account, it's the *only* way in.

This makes ingesting demo content moot: there is no account left for it to live on that the public
demo would ever use.

## Acceptance Criteria

- [x] `POST /query` rejects any request without a valid `Authorization: Bearer <token>` +
      `X-RAG-CSRF-Token` session (401 Unauthorized), before the graph is built or run
- [x] `get_graph()` (API/UI) and `_get_retrieval_client()` (UI) no longer fall back to a fixed
      service account — both now require a real `UserSession`
- [x] Demo UI: both tabs refuse to query ("Please log in...") until the visitor logs in with their
      own `enterprise-rag-platform` account; the login accordion is no longer described as optional
- [x] `docs/architecture.md`'s diagram and `README.md` updated to describe auth as required, not
      optional, with no service-account path
- [x] Tests updated/added: 401-without-session on the API, login-required short-circuit on both UI
      tabs (`tests/api/test_router.py`, `tests/ui/test_app.py`)

## Notes

**Resolved (2026-10-01):** implemented as a removal, not an addition. `app/api/router.py`'s
`get_graph()` now takes a mandatory `UserSession` (no `| None` default) and the `/query` endpoint
raises `HTTPException(401, ...)` when `extract_user_session()` returns `None`. `app/ui/app.py`'s
`run_direct_query`/`run_agentic_query` return a login-required message instead of calling the
(now session-only) `_get_retrieval_client()`/`get_graph()` when no session is present. The original
`RAG_PLATFORM_EMAIL`/`PASSWORD` settings remain, but only as a local-dev convenience for running
`app/mcp_server/server.py` standalone, outside the API/UI's per-caller session flow — they are no
longer reachable from either real entry point. 79 tests passing, ruff/mypy clean.
