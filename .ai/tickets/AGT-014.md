# AGT-014 — Gradio Login Flow (User-Facing Half of AGT-013)

Status: Backlog
Depends On: AGT-013
Category: Improvement

## Description

`AGT-013` makes the backend accept a per-user RAG-platform token; this ticket is what actually
gets a real user that token: a login step in the Gradio demo UI (`app/ui/app.py`) that calls the
RAG platform's own `POST /auth/login` directly (no new identity system in `agentic-ai`), holds the
resulting access token in Gradio session state, and uses it for both the Direct RAG and Agentic
RAG tabs so a logged-in visitor genuinely sees their own documents in both.

## Acceptance Criteria

- [ ] A login component (email/password fields, matching what the RAG platform's own `/auth/login`
      expects) gated in front of, or alongside, the existing two tabs
- [ ] Successful login stores the access token in `gr.State` (per-browser-session, not global)
- [ ] Both `run_direct_query` and `run_agentic_query` use the logged-in token when present, via
      `AGT-013`'s new `Authorization` header support
- [ ] No login = today's behavior unchanged (fixed service account, no regression for a casual demo
      visitor who doesn't want to log in)
- [ ] A clear, non-crashing message when a token expires mid-session (RAG-platform access tokens
      are short-lived) rather than a confusing failure

## Notes

Deliberately no "remember me" / persistent session beyond the browser tab — this is a demo UI, not
a product with real session management requirements.
