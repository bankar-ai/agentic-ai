# AGT-034 — Direct vs Agentic RAG Tabs in the Vercel Frontend

Status: In Progress
Depends On: None
Category: Feature

## Description

`app/ui/app.py`'s local Gradio demo already has a two-tab "Direct RAG vs. Agentic RAG" comparison
(single retrieval pass, no synthesis vs. the full Gatekeeper→Research→Writer→Verifier pipeline),
specifically built to show the value of the correction loop, not just describe it. It was never
deployed anywhere public — only the FastAPI backend (Cloud Run) and the React frontend (Vercel)
are live, and the live frontend is agentic-only with no comparison. Port that same comparison into
the live frontend.

## Acceptance Criteria

- [ ] New `POST /query/direct` endpoint, reusing the exact logic `app/ui/app.py`'s
      `run_direct_query` already has (single retrieval pass, `top_k=1`, the top chunk's raw text
      returned as-is, no LLM synthesis) — extracted into a shared function both the Gradio UI and
      this new endpoint call, not duplicated
- [ ] Frontend: a mode toggle (Direct / Agentic) on the query page. Direct mode calls the new
      endpoint and shows the raw top chunk + its source filename; Agentic mode is the existing
      `/query` flow, unchanged
- [ ] Both modes share the same login/session, documents panel, and history (Direct results get
      saved to history too, labeled as such, so a side-by-side comparison is possible from the
      history panel alone)
- [ ] Tests: new endpoint's auth requirement, empty-results case, a real retrieval case (mocked
      client)
- [ ] Deployed and live-verified: a real query in both modes against the project owner's own
      account, compared side by side
