# AGT-030 — LLM Token/Cost Consumption Metrics

Status: In Progress
Depends On: None
Category: Improvement

## Description

The project owner wanted to see OpenRouter consumption for `agentic-ai`'s own LLM calls,
comparable to `enterprise-rag-platform`'s. Nothing previously captured per-call token counts or
cost at all — only Langfuse's point-in-time trace events, which don't aggregate into "how much has
this cost so far."

## Acceptance Criteria

- [x] `app/core/llm_usage_metrics.py`: `record_llm_usage()` reads real token counts off
      PydanticAI's `RunResult.usage` (model-agnostic, always populated) and the actual model that
      produced the response off `RunResult.response.model_name` (correctly attributes
      `FallbackModel` calls to whichever sub-model actually ran, not just the configured primary)
- [x] `agentic_ai_llm_tokens_total` counter (labeled agent/model/token_type) and
      `agentic_ai_llm_cost_usd_total` counter (labeled agent/model, computed from an explicit
      per-model USD/token price table — an unpriced model records real tokens but `$0` cost,
      visibly, rather than a silently wrong estimate)
- [x] Wired into all three LLM call sites: `gatekeeper.py`, `writer.py`, `verifier.py`
- [x] Tests: `tests/core/test_llm_usage_metrics.py` (4 cases)
- [x] Full suite green, ruff/mypy clean
- [ ] New Grafana panel on the `agentic-ai` dashboard showing cost/token consumption
- [ ] Deployed and live-verified: a real query produces real, non-zero metric samples

## Notes

`enterprise-rag-platform`'s own consumption is checked directly against OpenRouter's own
`/api/v1/auth/key`/`/api/v1/credits` APIs (real billing truth) rather than re-instrumented here —
that's a separate repo, out of this ticket's scope to modify. Both projects' real-time spend is
comparable by checking each project's own dedicated API key's live usage figures.
