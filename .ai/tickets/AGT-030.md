# AGT-030 — LLM Token/Cost Consumption Metrics

Status: Done
Depends On: None
Category: Improvement

## Description

The project owner wanted to see OpenRouter consumption for `agentic-ai`'s own LLM calls,
comparable to `enterprise-rag-platform`'s. Nothing previously captured per-call token counts or
cost at all — only Langfuse's point-in-time trace events, which don't aggregate into "how much has
this cost so far."

## Acceptance Criteria

- [x] `app/core/llm_usage_metrics.py`: `record_llm_usage()` reads real token counts off
      PydanticAI's `RunResult.usage` (model-agnostic, always populated) and the actual model that
      produced the response off `RunResult.response.model_name` (correctly attributes
      `FallbackModel` calls to whichever sub-model actually ran, not just the configured primary)
- [x] `agentic_ai_llm_tokens_total` counter (labeled agent/model/token_type) and
      `agentic_ai_llm_cost_usd_total` counter (labeled agent/model, computed from an explicit
      per-model USD/token price table — an unpriced model records real tokens but `$0` cost,
      visibly, rather than a silently wrong estimate)
- [x] Wired into all three LLM call sites: `gatekeeper.py`, `writer.py`, `verifier.py`
- [x] Tests: `tests/core/test_llm_usage_metrics.py` (4 cases)
- [x] Full suite green, ruff/mypy clean
- [x] New Grafana panels on the `agentic-ai` dashboard: cost per hour by model, tokens per hour
      by agent, all-time total cost stat
- [x] Deployed and live-verified: a real query produces real, non-zero metric samples

## Resolution (2026-10-04)

Deployed as `agentic-ai-00025-nvw`, then `agentic-ai-00026-5dp` after a real bug was found and
fixed (below). Live-verified end-to-end with a real query:

- `agentic_ai_llm_tokens_total` confirmed correct from the first deploy: real, properly-labeled
  samples (e.g. `agent="gatekeeper", model="google/gemma-3-27b-it", token_type="input"` = 640).
- **A real bug found and fixed**: `agentic_ai_llm_cost_usd_total` never appeared under its own
  name. Root-caused by checking the full metric catalog (`/api/v1/label/__name__/values`) rather
  than assuming an export-timing lag — the counter's `unit="USD"` kwarg got appended by the
  OTel-to-Prometheus export bridge, silently renaming the series to
  `agentic_ai_llm_cost_usd_USD_total`. Not catchable by the existing unit tests, since
  `InMemoryMetricReader` doesn't exercise that bridge. Fixed by dropping the redundant `unit=`
  kwarg (the metric name already says "usd" in plain text), redeployed, re-verified: real
  per-agent cost data under the correct name (gatekeeper $0.0000742, writer $0.0001961, verifier
  $0.0001159 for one query — $0.00039 total). Dashboard's "agentic-ai total LLM cost (all-time)"
  stat panel confirmed showing `$0.0004` via the render API.
- One cosmetic follow-up noted, not blocking: the "LLM cost per hour, by model" timeseries panel
  auto-scales its y-axis to $0–$100, making data at these tiny real amounts hard to read visually
  (the underlying data point is there, just small). Worth a fixed/smaller axis range later.

## Notes

`enterprise-rag-platform`'s own consumption is checked directly against OpenRouter's own
`/api/v1/auth/key`/`/api/v1/credits` APIs (real billing truth) rather than re-instrumented here —
that's a separate repo, out of this ticket's scope to modify. Both projects' real-time spend is
comparable by checking each project's own dedicated API key's live usage figures.
