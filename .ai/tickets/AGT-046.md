# AGT-046 — Trace Citations: Show Which Documents/Sources Were Actually Retrieved

Status: Done
Depends On: None
Category: Feature

## Description

Found 2026-10-05: the project owner asked "which docs were retrieved?" and "verifier says
grounded -- grounded in which document?" and the honest answer is the frontend has no way to show
this, because the **backend never traces it**. Confirmed in `app/graph/build.py`:

- `research_node`'s trace step is `{"agent": "research", "evidence_count": N}` -- the count only,
  never the actual `Evidence` list (`text`/`source`/`citation` -- confirmed each item's `citation`
  field is the real source filename for KB evidence, `app/agents/research.py:101`, or the real
  URL for web evidence, `app/agents/web_search.py:35`)
- `writer_node`'s trace step is `{"agent": "writer", "text": draft.text}` -- never
  `draft.cited_evidence`, the actual list the Writer claims to have drawn on

So today there is genuinely no way for a user (or for the Verifier's own trace, see `AGT-039`) to
see which specific documents or URLs backed an answer. This is a new capability, not a regression
-- it was simply never built.

## Acceptance Criteria

- [x] `research_node`'s trace step includes each piece of evidence's `source` (`knowledge_base`/
      `web`) and `citation` (filename or URL) -- not the full `text` (keeps the trace payload
      reasonably sized; the Writer's draft already quotes/paraphrases the relevant content)
- [x] `writer_node`'s trace step includes `cited_evidence` (same `source`/`citation` shape) so the
      Verifier's "grounded" determination can be traced back to specific sources, not just
      asserted
- [x] Frontend's `TraceStepper` (`AGT-039`) renders these as a citations list under the Research
      and Writer nodes -- `knowledge_base` citations shown as the filename (plain text, no public
      URL to link to from this app); `web` citations rendered as real clickable links
      (`<a href>`), since the citation *is* a URL
- [x] Deployed and live-verified against a real query: confirm the actual filename(s)/URL(s) used
      appear in the trace, matching what the Verifier's reasoning references

## Notes

Directly answers two of the project owner's questions in one pass: "which docs were retrieved"
(Research's new citation list) and "grounded in which document" (Writer's `cited_evidence`,
which is exactly what `verify_answer()` already checks against -- see
`app/agents/verifier.py`'s `_evidence_key` matching). No schema changes needed to `Evidence`
itself, just what gets put into the trace `dict`.

## Resolution (2026-10-05)

Both nodes now include `"citations": [{"source": ..., "citation": ...} for ...]` in their trace
steps. Frontend's new `CitationsList` component renders them under Research/Writer, web citations
as real `<a href>` links, knowledge_base as plain filename text. New backend test
(`test_research_and_writer_nodes_trace_citations`) confirms the shape. **Live-verified against a
genuinely fresh real query** (not a cache replay): "What should workers wear when working at
heights on scaffolding?" returned real citations
(`scaffmag.com/industry-hub/topics/ppe-requirements/`,
`skilled.peopleready.com/worker-resources/...`, `hsestudyguide.com/ppe-requirements-for-scaffolding-work/`)
on both the Research and Writer steps, and the Verifier's `reasoning` referenced those same three
sources by name -- directly confirms this answers the original "grounded in which document"
question. Deployed as part of commits `3b267aa`/`ace5c4e` on `main`.
