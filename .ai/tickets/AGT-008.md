# AGT-008 — True Per-Step SSE/UI Streaming

Status: Done
Depends On: None
Category: Improvement

## Description

`POST /query` and the Gradio UI's Agentic RAG tab both currently run the full graph to completion
(`graph.ainvoke`) before sending anything — the SSE response delivers every `step` event at once,
not as each agent actually finishes, despite the spec's Serving section describing live streaming
as the point of the SSE endpoint. Flagged in the final whole-branch review (`I-6`) and explicitly
scoped out of that fix wave as a documented fast-follow (only the docstrings were corrected to
stop claiming "live" behavior that doesn't exist).

## Acceptance Criteria

- [ ] `app/api/router.py`'s `_event_stream` uses `graph.astream(initial_state, stream_mode=...)`
      (verify the exact mode against the installed `langgraph` API — this repo's own convention is
      "don't guess, check the installed package" for every library integration) and yields each
      node's trace entry as it actually completes, not after the whole graph finishes
- [ ] `app/ui/app.py`'s Agentic RAG tab becomes a progressively-yielding async generator so the
      trace visibly fills in during a query, matching the demo's original intent (a live
      side-by-side comparison with Direct RAG)
- [ ] Docstrings updated back to accurately describe the new (genuinely live) behavior
- [ ] Existing tests updated/extended to cover incremental yielding, not just the final state

## Notes

Not blocking any deployment work — purely a demo-polish improvement. Worth doing before a live
interview walkthrough, since "watch the agents reason live" is a meaningfully stronger demo moment
than the current batch-delivery behavior.

**Resolved (2026-10-04):** verified against the installed `langgraph` API first (its own
convention) — `stream_mode="updates"` yields one `{node_name: full_state}` chunk per node as it
actually completes (confirmed interactively against this exact graph before changing any code).
`app/api/router.py`'s `_event_stream` now iterates `graph.astream(initial_state,
stream_mode="updates")`, yielding each `step` SSE event as its node finishes rather than batching
them after `ainvoke()` returns; steps already yielded before a later mid-stream failure stay
sent. `app/ui/app.py`'s `run_agentic_query` is now an async generator for the same reason —
Gradio streams its output components on every `yield`. Live-verified with per-line timestamps
against the real deployment: `gatekeeper` arrived at T+0s, `research` at T+4s, `writer` at
T+19s, `verifier` at T+21s, `result` at T+21s -- genuinely incremental, not a batch at the end.
