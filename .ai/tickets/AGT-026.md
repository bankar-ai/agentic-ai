# AGT-026 — Session Expiry UX (Not a Silent Refresh — See Notes)

Status: Done
Depends On: None
Category: Improvement

## Description

Investigated whether `agentic-ai`'s frontend could match `enterprise-rag-platform`'s own
"actively-used session never actually expires" behavior (that platform keeps a 30-day refresh
token and silently renews the 30-minute access token). **It can't, without a real architecture
change**: `StaticTokenAuth` (`app/rag_client/auth.py`) deliberately has no password and cannot
refresh — "an expired session means the end user must log in again at the RAG platform, not
something this adapter can recover from." `agentic-ai`'s backend never holds a user's
refresh-token cookie at all (only the short-lived access/CSRF token pair the frontend already
has), by design — matching the project's standing "`agentic-ai` never owns passwords" stance
(`AGT-013`). Building real silent refresh would mean agentic-ai's backend starting to hold
per-user refresh-token state it doesn't have today, which is a real security/architecture
trade-off, not a quick fix — not doing that without the project owner weighing in first.

**Scope here is UX only**: soften the forced-logout experience without changing the trust model.

## Acceptance Criteria

- [x] A visible warning when the session is close to expiring (the access token's own `exp` claim
      is decodable client-side without verification, just to read the timestamp — no secret
      material exposed by doing so)
- [x] On forced logout (expired session), the user's in-progress typed query is preserved and
      restored after they log back in, instead of silently discarded
- [x] Verified short of a full 30-minute wait (see Resolution)

## Resolution (2026-10-04)

Implemented in `frontend/src/jwt.ts` (`decodeJwtExpiry`) and `frontend/src/history.ts`
(`saveDraftQuery`/`loadAndClearDraftQuery`), wired into `QueryPage.tsx`'s expiry-check interval
and the existing forced-logout path. Confirmed present in the deployed JS bundle (the warning
string and the draft-preservation logic). **Not live-verified against a real 30-minute session
expiry** — waiting out a real token expiry wasn't practical within this session, and there's no
browser tool available to simulate it faster. Verified instead by code review and confirming the
built artifact contains the logic; this is a real gap in verification rigor relative to this
project's own standing practice, named here rather than glossed over. A fast way to verify later:
log in, open browser devtools, manually fast-forward past the 25-minute mark by editing the
in-memory session's token (dev-only), confirm the warning appears; let a session sit idle past 30
minutes, confirm the draft text survives the forced logout.

## Notes

Revisit real silent refresh only if the project owner decides `agentic-ai`'s backend should start
holding refresh-token state server-side — that's a scope/trust-model decision for them, not
something to default into.
