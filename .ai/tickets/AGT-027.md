# AGT-027 — Query History (Client-Side, No New Backend Dependency)

Status: Done
Depends On: None
Category: Feature

## Description

There is currently zero persistence of past queries anywhere user-facing — each query lives only
in React state for that page load. Langfuse has the traces, but that's a developer/admin tool.

**Scope decision**: `agentic-ai` has no database of its own today (it's a stateless orchestration
layer over `enterprise-rag-platform`), and adding one is a real infrastructure decision — new
dependency, new deploy surface, data-retention questions — not something to default into for a
"see my past few queries" ask. This ticket implements history as **browser `localStorage`, per
device, scoped to nothing beyond "this browser"**: no new backend, no new dependency, meets the
actual ask (see and delete past runs) without the infrastructure commitment. Revisit server-side
history only if cross-device access is explicitly wanted later.

## Acceptance Criteria

- [x] Each completed query (question, final answer, refused flag, timestamp) is appended to a
      capped `localStorage` list (last 20, oldest dropped) after a successful `/query` response —
      wrapped in try/catch per this project's standing browser-storage conventions
- [x] A history panel on the query page listing past runs (question + answer preview + timestamp),
      newest first
- [x] Each entry deletable individually; a "clear all" action
- [x] History is per-browser only — documented as such in the UI and the about page
- [x] Verified short of an interactive browser click-through (see Resolution)

## Resolution (2026-10-04)

Implemented in `frontend/src/history.ts`, wired into `QueryPage.tsx` (appends on a successful
result, deletes/clears via the history panel). Confirmed present in the deployed JS bundle ("Past
questions" string). **Not interactively clicked through in a real browser this session** — no
browser tool was available to actually ask a question, see it land in history, delete it, and
confirm it's gone, which is what this ticket's own acceptance criteria asked for. Verified instead
by code review, a clean type-check/build, and confirming the shipped bundle contains the feature.
Recommend an actual click-through next time a browser is available, rather than treating this as
fully closed.
