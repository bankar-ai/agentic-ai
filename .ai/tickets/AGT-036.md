# AGT-036 — Response Time: Frontend Display + Dashboard Metric

Status: Done
Depends On: None
Category: Improvement

## Description

The project owner wants to see how long a query actually took, both as something shown in the
live app and as a proper dashboard metric. Today the only latency visibility is the generic "HTTP
request duration, p50/p95 (all endpoints)" panel (`AGT-021`) — diluted across `/health`,
`/auth/login`, `/documents`, and `/query` all together, not `/query`-specific, and nothing is
shown to the end user in the UI at all.

## Acceptance Criteria

- [x] Backend: the final SSE `result` event on `/query` (and the new `/query/direct`, `AGT-034`)
      includes `duration_seconds` — measured server-side, start of `_event_stream` to the final
      event, the authoritative number (excludes client network overhead, which a client-side
      stopwatch would include)
- [x] New dedicated metric `agentic_ai_query_duration_seconds` (histogram, labeled by `outcome`
      and `mode` [agentic/direct]) — distinct from the generic all-endpoints HTTP panel
- [x] New dashboard panel: query duration p50/p95, by outcome/mode
- [x] Frontend: the response time is shown next to the answer (and in each history entry) using
      the server-reported `duration_seconds`, not a client-side timer
- [x] Deployed and live-verified: a real query shows a real duration in the UI, and the same
      number is confirmed in Prometheus

## Resolution (2026-10-04)

Deployed as revision `agentic-ai-00034-stp` (backend) + the frontend's GitHub auto-deploy.
Live-verified both endpoints report real durations: `/query/direct` returned
`duration_seconds: 3.3567454140000024`, the full agentic `/query` returned
`duration_seconds: 101.725853861` for a two-retry run. `agentic_ai_query_duration_seconds_count`
confirmed in Prometheus for both `mode="agentic"` and `mode="direct"`. The dashboard's
`histogram_quantile` panel itself showed no line yet at first verification -- expected, not a bug:
`rate()` needs at least two samples across its window, and this metric had only just been created
by the very query used to verify it.

**Re-verified 2026-10-04, later same day**, with the project owner's real account again (fresh
login against `/auth/login`): `/query/direct` returned `duration_seconds: 6.369922163999945`
(fall-protection-training query, `Safety Guidelines.pdf`), the full agentic `/query` returned
`duration_seconds: 101.29852726700005` for a two-retry run. Prometheus
`sum by (mode) (agentic_ai_query_duration_seconds_count{service_name="agentic-ai"})` now shows
`{mode="agentic"}: 3` and `{mode="direct"}: 3` -- real accumulated samples, not just the one from
first verification. The dashboard's "Query duration, p50/p95, Agentic vs Direct" panel (`arxchd`,
panel id 141) now renders real points: p95 agentic ~4.17 min, p50 agentic ~2.92 min, p50/p95
direct both near 0s on the chosen time window -- confirming the panel populates correctly now that
more than one sample exists, as predicted.
