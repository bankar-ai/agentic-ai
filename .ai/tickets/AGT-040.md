# AGT-040 — History: Click-to-Reopen, Capped at 5 Shown

Status: Done
Depends On: AGT-037, AGT-039
Category: Improvement

## Description

Past queries are listed (`localStorage`-backed, `AGT-027`) but clicking an entry does nothing —
you only ever see the truncated inline text. Make each history row clickable: it re-renders that
entry's full result (answer, verdict, and trace if it has one) into the main result panel, reusing
the same display `AGT-039` builds for a live query's result, from data already stored in the entry
(no network round trip needed to "reopen" one).

Cap the visible list at the 5 most recent entries (older ones aren't deleted from `localStorage`,
just not shown) — `AGT-041`'s server-side history is the durable long-term store; this client-side
list is now explicitly just "your last 5, quickly reopenable," not a growing unbounded log.

## Acceptance Criteria

- [x] History panel shows at most the 5 most recent entries
- [x] Clicking a history entry re-renders its stored answer/verdict/trace into the main result
      panel (same visual treatment `AGT-039` gives a live result), without a network call
- [x] The currently-open history entry (if any) is visually indicated as selected/active
- [x] Existing delete/clear-all behavior is unchanged
- [x] Desktop/laptop viewport only — see `AGT-042`
- [x] Deployed; verified by code review + build (see Resolution for what a real-browser click-test
      would still add)

## Notes

Depends on `AGT-039` existing first since "reopen" reuses that ticket's result-rendering
components rather than duplicating them.

## Resolution (2026-10-04)

`HistoryEntry` extended with `trace`/`sourceFilename` (previously not stored at all -- the trace
would have had nothing to reopen into). `history.ts` exports `MAX_ENTRIES_SHOWN = 5`;
`QueryPage.tsx` slices to that for display while still storing up to 20. Clicking an entry builds
a `DisplayResult` straight from the stored fields (`entryToDisplayResult`) and renders it through
the same `ResultPanel` a live query uses -- no network call. The open entry gets a highlighted
background (`selectedHistoryId` state). Deployed as part of commit `365d7f1` on `main`; build and
type-check clean, and the stored-entry-to-`DisplayResult` mapping was traced by hand against both
real trace shapes captured in `AGT-039`'s resolution to confirm it round-trips correctly. **Not
yet physically click-tested in a real browser** -- I have no browser/screenshot tool in this
session, so "appears in history and reopens on click" is verified by code review and the API/
build checks above, not by an actual click. Flagging this honestly rather than overclaiming; the
project owner clicking through it live would be the real confirmation.
