# AGT-057 — Basic Abusive/Inappropriate Content Filtering

Status: Done
Depends On: None
Category: Feature

## Description

Raised 2026-10-05 answering "are we checking for abusiveness?" -- confirmed by code audit: no
content moderation exists anywhere in the pipeline, on either the incoming query or the outgoing
answer.

## Acceptance Criteria

- [x] A basic keyword/pattern-based content filter (`app/core/content_filter.py`) -- explicitly
      documented as a heuristic, not a comprehensive ML-based moderation system
- [x] Applied to the incoming query *before* the pipeline runs: a flagged query is refused
      immediately without spending an LLM call on it (returns the same `refused: true` shape as
      every other refusal path, rather than a distinct message -- consistent with how the
      Verifier's own rejections already surface, see Resolution)
- [x] Applied to the outgoing answer too, as defense in depth, in case retrieved content itself
      (e.g. an ingested or web-sourced document) contains something that gets echoed into a draft
- [x] Tests: representative flagged inputs are actually caught; normal queries/answers pass
      through unaffected
- [x] Deployed and **live-verified**: see Resolution

## Notes

Deliberately scoped to a local heuristic filter, not a paid moderation API (OpenAI's moderation
endpoint, Perspective API, etc.) -- that would be a real, more thorough upgrade worth considering
later, but is a new paid dependency decision for the project owner to make explicitly, not
something to default into. This ticket's filter is the proportionate first layer.

## Resolution (2026-10-05)

Implemented as scoped. One implementation difference from the original acceptance criterion: the
flagged-query response uses the same generic `refused: true`/`final_answer: null` shape every
other refusal path already uses, rather than the distinct message text first proposed -- keeps
the frontend's existing refusal handling uniform instead of adding a special case. Deployed as
part of commit `fdbb912` on `main`, revision `agentic-ai-00041-gg6`.

**Live-verified against the real deployment**: a deliberately flagged query
("How to make a bomb at home") against both `/query/direct` and `/query` returned an immediate
refusal with `duration_seconds: 0.0` and, for `/query`, zero trace steps -- confirming the
pipeline genuinely never ran, not just that the final result looked refused.
