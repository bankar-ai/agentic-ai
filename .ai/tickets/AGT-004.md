# AGT-004 — Add a Hosted LLM Provider (OpenRouter) Alongside Local Ollama

Status: Backlog
Depends On: None
Category: Improvement

## Description

This project's agents currently only know how to talk to a local Ollama instance
(`app/agents/llm.py`'s `get_ollama_model`). That's fine for local dev, but the portfolio's shared
`infrastructure-options.md` already named **OpenRouter** as this project's LLM inference provider
for anything beyond a local machine — and now there's a concrete reason why: the existing
`enterprise-rag-platform` GCP VM (`rag-platform-host`, ~958MB RAM) has no realistic room for
Ollama plus a tool-capable model. Deploying this project anywhere other than a developer's own
machine needs a hosted-LLM code path.

This also plausibly helps `AGT-010` (Writer/Verifier structured-output reliability) "for free" —
hosted frontier/well-tool-tuned models are generally far more reliable at tool-calling than small
local models, so picking a solid OpenRouter model for the deployed path may reduce or eliminate
that flakiness there even if it's not separately fixed.

## Acceptance Criteria

- [ ] A new model-provider function (e.g. `get_openrouter_model(settings)` in `app/agents/llm.py`,
      or a small `app/agents/llm_providers/` split if that file would otherwise grow unwieldy)
      building a PydanticAI model pointed at OpenRouter's OpenAI-compatible endpoint
- [ ] `Settings` gains the needed config (API key, model name, base URL — OpenRouter's is fixed,
      so likely just the first two) and a way to select which provider is active (e.g. an
      `LLM_PROVIDER` setting: `"ollama"` | `"openrouter"`), defaulting to `ollama` so local dev
      behavior is unchanged
- [ ] `get_graph()` (and the UI's equivalent) picks the model via this new selection rather than
      being hardcoded to `get_ollama_model`
- [ ] Verify against the actually-installed `pydantic-ai-slim` API, the same "don't guess"
      discipline the rest of this codebase follows for library integrations (see the Task 4/6/9/15
      adaptations in `.ai/sessions/` for the pattern — prior library-API assumptions in this repo
      needed real adaptation more often than not)
- [ ] Tests: unit test for the provider-selection logic; no live OpenRouter call needed in the test
      suite (same pattern as the existing Ollama provider test)
- [ ] `.env.example` updated with the new variables, documented

## Notes

**Needs a decision before implementation, not just before deployment**: whether to reuse
`enterprise-rag-platform`'s existing funded OpenRouter account (same API key, shared billing
across two projects) or provision a separate one for this project. See
`.ai/memory/decisions-in-progress.md`.

Model choice on OpenRouter itself (which model to default to for the deployed path) is a second,
smaller decision — OpenRouter's free tier (`:free` models, 20 req/min, 50 req/day at $0 balance)
may or may not have a genuinely tool-call-reliable option; worth checking current options rather
than assuming, per `CLAUDE.md`'s "Research Before Recommending" rule for fast-evolving LLM-API
choices.
