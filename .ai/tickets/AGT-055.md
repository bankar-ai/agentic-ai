# AGT-055 — Idle-Timeout Logout (30 min), Matching enterprise-rag-platform's Own Convention

Status: Done
Depends On: AGT-051
Category: Bug

## Description

Raised 2026-10-05, directly following `AGT-051`: once the backend silently refreshes an expired
access token behind the scenes, there's no longer anything that logs an inactive user out at all
-- a session can now stay alive indefinitely (up to the refresh token's real 30-day server-side
lifetime, confirmed in `enterprise-rag-platform`'s own `app/auth/config.py`), even if the user
walked away and never touched the page again. That's a regression in safety, not something
`AGT-051` intended to remove -- it just happened to, as a side effect of making expiry invisible.

Investigated `enterprise-rag-platform`'s own frontend for the expected behavior here, not guessed
at: it already has exactly this feature, confirmed in `frontend/src/lib/activityTracker.ts` +
`apiClient.ts`'s `tryRefresh()` -- tracks real user interaction (click/keydown) in `localStorage`,
and before attempting a silent refresh, checks whether more than `IDLE_TIMEOUT_MS` (30 minutes,
matching `access_token_expire_minutes`) has passed since the last interaction. If so, it skips the
refresh entirely and forces a logout, rather than silently keeping an abandoned session alive.
This is purely client-side in that platform's own frontend bundle -- `agentic-ai`'s backend calls
`/auth/refresh` directly, server-to-server, and never runs that code, so it never inherited this
protection automatically.

Also found while investigating this: `agentic-ai`'s existing "session will expire soon" warning
(`AGT-026`, `QueryPage.tsx`'s `EXPIRY_WARNING_WINDOW_MS`/`decodeJwtExpiry`) is now **actively
misleading** post-`AGT-051` -- it still fires based on the original access token's expiry, but the
backend now silently refreshes that token without ever telling the frontend, so the user will
*not* actually need to log in again when it fires. This warning should be replaced by the new
idle-timeout logic, not left alongside it.

## Acceptance Criteria

- [x] New client-side idle tracker (`frontend/src/activityTracker.ts`), mirroring
      `enterprise-rag-platform`'s own: records real user interaction (click/keydown),
      `IDLE_TIMEOUT_MS = 30 * 60 * 1000`, degrades gracefully (never idle-timed-out) if
      `localStorage` is unavailable
- [x] `QueryPage.tsx` starts tracking on mount and periodically checks idle status (same 30s
      cadence as the interval this replaces); past the threshold, forces logout (clear session,
      redirect to `/`, draft preserved via `saveDraftQuery` if a question was mid-typed) -- same
      `logout()`/`navigate("/")` pattern the existing forced-logout-on-expired-session path
      already uses
- [x] The stale "session will expire soon" warning (`AGT-026`'s `EXPIRY_WARNING_WINDOW_MS`/
      `decodeJwtExpiry` logic) is removed, not left running alongside the new idle check --
      `jwt.ts` deleted too, since its only caller is gone
- [x] Deployed; verified by code review + build output + direct bundle inspection (no browser
      tool this session to physically sit idle for 30 minutes and watch it fire)

## Notes

Directly requested by the project owner after confirming `enterprise-rag-platform`'s own idle-
timeout is purely client-side and doesn't protect `agentic-ai` automatically. Scoped to match that
platform's existing UX convention (30 min, click/keydown tracking) rather than inventing a new
threshold or mechanism.

## Resolution (2026-10-05)

Implemented exactly as scoped. `frontend/src/activityTracker.ts` is a close mirror of
`enterprise-rag-platform/frontend/src/lib/activityTracker.ts` (own `localStorage` key, same
`IDLE_TIMEOUT_MS`). `QueryPage.tsx`'s old `EXPIRY_WARNING_WINDOW_MS`/`decodeJwtExpiry` effect
replaced with one that calls `startActivityTracking()` on mount and checks `isIdleTimedOut()`
every 30s; past the threshold it preserves any in-progress draft (via a `queryRef` to avoid a
stale-closure bug the naive version would have had -- the interval's callback is only re-created
when `session`/`logout`/`navigate` change, not on every keystroke) and forces logout. `jwt.ts`
deleted as fully dead code once its only caller was removed. Build and `oxlint` clean (back to
the same 2 pre-existing warnings as before this change, no new ones). Deployed as part of commit
`d33577e` on `main`; confirmed live via direct bundle inspection (`agentic-ai.last-activity`
string present in the deployed JS).
