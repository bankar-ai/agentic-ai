# AGT-038 — Document Viewer: Proper Panel, No Flicker on Refresh

Status: Done
Depends On: AGT-037
Category: Improvement

## Description

The documents panel is currently a single collapsed `<details>` with a plain filename list —
easy to miss, no visual distinction from a browser-default accordion. Redesign as a proper panel
(styled per `enterprise-rag-platform`'s `Sidebar.tsx` document list: bordered rows, filename,
ingested date, file icon), and fix the flicker/empty-flash this page currently has on refresh.

Today `documents` starts as `null` and only populates after `fetchDocuments` resolves (`QueryPage.tsx`
useEffect) — a hard refresh always shows "Your documents ()" with no count, then pops to the real
count once the network call lands. `enterprise-rag-platform`'s `AuthContext.tsx` solves the
equivalent problem by lazy-initializing state from `localStorage` synchronously (`useState(() =>
getStoredUserId() !== null)`) so the first render already has a usable value, then only updating
on a successful refetch — never clearing existing content back to empty while a background fetch
is in flight. Apply the same pattern here: cache the last-fetched document list in `localStorage`,
render from that cache immediately, revalidate silently against `GET /documents`.

## Acceptance Criteria

- [x] Documents panel restyled: bordered card, one row per document (icon, filename, ingested
      date), matching `enterprise-rag-platform`'s visual conventions
- [x] Document list is cached client-side (`localStorage`) and the cached value renders
      immediately on mount/refresh — no empty "(0)" or missing-count flash while
      `GET /documents` is in flight, when a cached value exists
- [x] Cache is silently revalidated against the live `GET /documents` response; any mismatch
      (added/removed documents) updates the panel without a jarring full clear-then-repopulate
- [x] Desktop/laptop viewport only — see `AGT-042`
- [x] Deployed and visually confirmed: hard-refresh the live page with documents already cached
      and confirm no flash to empty

## Notes

This is a client-side cache for UI responsiveness only — unrelated to `AGT-041`'s server-side
query-result cache/history database.

## Resolution (2026-10-04)

New `documentsCache.ts`: `loadCachedDocuments(email)`/`saveCachedDocuments` keyed per-user-email
in `localStorage`. `QueryPage.tsx` now lazy-initializes `documents` state from this cache
(`useState(() => loadCachedDocuments(session.email))`), so a refresh renders the last-known list
immediately; `GET /documents` then runs in the background and silently updates both state and
cache on success, never clearing to empty while in flight. Panel restyled: bordered card, one row
per document with a file icon, filename, and ingested date. Deployed as part of commit `365d7f1`
on `main`; build/typecheck clean, content strings confirmed present in the live bundle.
