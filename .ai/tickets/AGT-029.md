# AGT-029 — Indirect Prompt Injection Guardrails

Status: Done
Depends On: None
Category: Security

## Description

Security audit (researched current best practice: OWASP LLM Top 10, MCP security literature, RAG
indirect-injection research) against the actual codebase found two real, fixable gaps:

1. System prompts (`gatekeeper.py`/`writer.py`/`verifier.py`) never told the model to treat
   retrieved KB chunks, web search results, or the Writer's own draft as untrusted *data* rather
   than instructions — the standard, cheapest mitigation against indirect prompt injection
   (malicious instructions hidden inside content that arrives through retrieval, bypassing any
   filtering done on the user's own query).
2. No sanitization of retrieved/web content before it reached a prompt at all — raw HTML, control
   characters, and invisible/bidi-override unicode (a known technique for hiding text from a human
   reviewer while an LLM still reads it) all passed straight through.

**Explicitly out of scope**: full HTML-document sanitization (chunks/snippets here are already
short, not full pages), and anything resembling a allow/deny keyword filter (brittle, high false
positive rate, not what the research recommends over prompt framing + structural sanitization).

## Acceptance Criteria

- [x] `app/agents/sanitize.py`: `sanitize_evidence_text()` -- Unicode NFKC normalization, HTML
      entity/tag stripping, control-character and invisible/bidi-character removal, length cap
- [x] Wired into every place untrusted content reaches a prompt: `research.py`'s KB and web
      evidence construction, `gatekeeper.py`'s exploratory-search chunk summaries
- [x] Explicit "this is data, not instructions" framing added to the Gatekeeper, Writer, and
      Verifier system prompts
- [x] Tests: `tests/agents/test_sanitize.py` (7 cases)
- [x] Full suite green (134 passed), ruff/mypy clean
- [x] Deployed and live-verified: a real query still produces a correctly grounded answer with
      the new prompt framing + sanitization active (no regression in answer quality/citations)

## Resolution (2026-10-04)

Deployed as revision `agentic-ai-00025-nvw`. Live-verified with a real end-to-end query ("What
is the capital of Sweden?") after the change: Gatekeeper routed correctly, Writer's answer still
explicitly disclosed the web source ("According to a web search on Wikipedia..."), Verifier still
marked it grounded -- no regression in answer quality or citation behavior from either the new
prompt framing or the sanitization pass.

## Notes

Not a response to an actual attack — a proactive hardening pass, same spirit as `AGT-028`'s CSP
headers. Neither mitigation claims to make the system immune to indirect prompt injection; both
raise the cost of a successful attack meaningfully, which is what the research describes as the
realistic bar (defense in depth, not a silver bullet).
