# AGT-017 — Standalone Frontend with a Real Login Page, Deployed to Vercel

Status: Done
Depends On: AGT-016
Category: Improvement

## Description

`enterprise-rag-platform` has a dedicated frontend (`frontend/`, Vite + React + TypeScript SPA,
deployed to Vercel, `ERP-043`) with its own login page, separate from its API. `agentic-ai` has
no equivalent — the only UI is the Gradio demo, a single page with a login accordion embedded
above the query tabs, not a separate login screen, and not deployed anywhere but the same Cloud
Run container as the API itself.

This ticket adds the missing piece: a real standalone frontend, mirroring the sibling project's
stack and deployment pattern, with an actual login page a visitor sees before anything else.

## Acceptance Criteria

- [ ] New `frontend/` directory: Vite + React + TypeScript SPA (same stack as
      `enterprise-rag-platform/frontend`, for portfolio consistency)
- [ ] A login page/route shown first: email + password, posts to `AGT-016`'s `POST /auth/login`,
      holds the returned `{access_token, csrf_token}` in memory only (React state, not
      `localStorage`/`sessionStorage`) — lost on refresh, matching the Gradio UI's own
      never-persisted-to-disk stance
- [ ] A query page/route, reachable only once logged in: a mode toggle (Direct RAG / Agentic RAG,
      mirroring the Gradio demo's two tabs) that calls `agentic-ai`'s `POST /query` with
      `Authorization`/`X-RAG-CSRF-Token` headers; Agentic mode renders the trace once the graph
      finishes (the API is batch-delivered, not per-step yet — see `AGT-008`) and the final answer
      or refusal
- [ ] A logout action that clears the in-memory session and returns to the login page
- [ ] An expired/rejected session (401 from `/query`) surfaces a clear "please log in again"
      message and returns to the login page, never a silent wrong answer
- [ ] `app/main.py` gains `CORSMiddleware`, configured via a new `CORS_ALLOWED_ORIGINS` setting
      (comma-separated, mirroring `enterprise-rag-platform/app/core/cors.py`'s exact pattern),
      defaulting to Vite's local dev origin (`http://localhost:5173`) only
- [ ] Deployed to Vercel: project root `frontend/`, `VITE_API_BASE_URL` set to the live Cloud Run
      URL; the Cloud Run service's `CORS_ALLOWED_ORIGINS` updated to the resulting Vercel origin
      and redeployed
- [ ] `gcp-deployment-tracker.md` gets a frontend entry alongside the existing `agentic-ai` Cloud
      Run entry, matching how the sibling project documents its own Vercel frontend
- [ ] `README.md` updated: this is now the primary way to use the project; the Gradio demo is kept
      as a side-by-side Direct-vs-Agentic comparison tool, not replaced

## Notes

Scope is deliberately lean (two routes, no component library, plain CSS) — this is a portfolio
demo frontend, not a production app. The Gradio UI is not being removed; it still exists for its
original comparison purpose.

**Resolved (2026-10-02):** `frontend/` (Vite + React + TS) deployed to Vercel at
`https://agentic-ai-psi-mauve.vercel.app`, calling the live Cloud Run backend. `app/main.py` gained
`CORSMiddleware` + `app/core/cors.py`, and the Cloud Run service was redeployed with
`CORS_ALLOWED_ORIGINS` set to the Vercel origin — live-verified: CORS preflight, login, and a full
`/query` round trip (Gatekeeper -> web_fallback -> Writer -> Verifier -> grounded answer) all
succeed from that exact origin.

**A real, consequential bug found integration-testing this (not a frontend bug — a pre-existing
one in `StaticTokenAuth`, since AGT-013):** every per-user session was failing every retrieval call
with `403 Missing or invalid CSRF token` on the live platform. Root cause: `StaticTokenAuth` set
only the `access_token` cookie, never the matching `csrf_token` cookie the platform's CSRF
double-submit check actually compares the `X-CSRF-Token` header against. A real browser session
gets that cookie for free (the platform sets it at login, non-httpOnly); a session *forwarded*
across process boundaries — the API's header path, the Gradio UI's login, and this frontend — never
had it until now. Fixed in `app/rag_client/auth.py`; this also silently fixes the same bug for the
existing Gradio multi-tenant path (`AGT-013`/`AGT-014`), which had the identical gap.
