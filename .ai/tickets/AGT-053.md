# AGT-053 — Question Input Doesn't Clear After a Query Completes

Status: Backlog
Depends On: None
Category: Bug

## Description

Found 2026-10-05: after a query finishes (successfully or not), the typed question stays sitting
in the input box. The project owner's own words: "I want the question to be cleared from the ask
once it is done -- for now question stays there even when its completion is done."

The one deliberate exception that must be preserved: `AGT-026`'s draft-preservation on a *forced
logout* (session expired mid-query) specifically re-populates the input with what was typed, so
that case should keep refilling it -- this ticket is about the normal "query finished" case, not
every case the input is ever set.

## Acceptance Criteria

- [ ] After a query completes successfully, the input clears
- [ ] After a query fails with a normal error (not a session-expiry redirect), decide and confirm
      one behavior: clearing it loses the question if the user wants to retry with the same text,
      but leaving it matches "can try again easily" -- default to clearing on success only, leaving
      it on error (so a failed query's text isn't lost), unless the project owner prefers otherwise
- [ ] `AGT-026`'s draft-preservation-on-forced-logout behavior is unchanged -- that's a distinct,
      deliberate case (the session expired mid-question, not "the question was answered")
- [ ] Deployed and visually confirmed: ask a question, confirm the input is empty once the answer
      appears

## Notes

Small, contained fix in `QueryPage.tsx`'s `handleSubmit` -- `setQuery("")` after a successful
result, most likely in the same branch that currently calls `setResult(display)`.
