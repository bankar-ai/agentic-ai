# AGT-016 — Backend Login Endpoint for a Future Standalone Frontend

Status: Done
Depends On: None
Category: Improvement

## Description

`enterprise-rag-platform` has a real deployed frontend (`frontend/`, Vite + React + TypeScript,
deployed to Vercel, `ERP-043`) with its own login page. `agentic-ai` has no equivalent — only the
Gradio demo's in-process login accordion (`app/ui/app.py`'s `login()`), which runs server-side in
the same Python process as the Gradio app and is never exposed as an API a separate frontend could
call.

A standalone SPA (`AGT-017`) cannot replicate that login flow by calling
`enterprise-rag-platform`'s `/auth/login` directly from the browser: that endpoint's tokens arrive
as **httpOnly cookies** (`ERP-116`) scoped to `enterprise-rag-platform`'s own origin, which
browser JS can never read — only server-side code (like `app/ui/app.py`'s `httpx.AsyncClient`
cookie jar) can. `agentic-ai`'s own API is a separate origin and uses the
`Authorization: Bearer` + `X-RAG-CSRF-Token` header contract (`AGT-013`), not cookies, so the
frontend needs `agentic-ai`'s own backend to do the httpOnly-cookie dance server-side and hand
back the extracted token pair in a plain JSON body instead.

## Acceptance Criteria

- [ ] The login logic currently inline in `app/ui/app.py`'s `login()` (call
      `RagPlatformAuth.get_csrf_token()`, read `access_token` back out of the http client's cookie
      jar) is extracted into a shared helper (e.g. `app/rag_client/auth.py` or a small new module)
      that both `app/ui/app.py` and the new endpoint below call — no duplicated logic
- [ ] New `POST /auth/login` route on `agentic-ai`'s own FastAPI app (`app/api/`), request body
      `{email, password}`, response `{access_token, csrf_token}` (200) on success or 401 on bad
      credentials — mirrors `extract_user_session`'s existing header contract so the response can
      be dropped straight into `Authorization`/`X-RAG-CSRF-Token` on a later `/query` call
- [ ] Never logs or persists the submitted password beyond the one proxied call
- [ ] Tests: success returns the token pair; bad credentials return 401; malformed/missing body
      returns 422
- [ ] `README.md`'s "Multi-tenant auth" section documents this endpoint as the way a non-Gradio
      client obtains a session
