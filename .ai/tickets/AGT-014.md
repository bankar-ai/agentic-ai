# AGT-014 — Gradio Login Flow (User-Facing Half of AGT-013)

Status: Done
Depends On: AGT-013
Category: Improvement

## Description

`AGT-013` makes the backend accept a per-user RAG-platform token; this ticket is what actually
gets a real user that token: a login step in the Gradio demo UI (`app/ui/app.py`) that calls the
RAG platform's own `POST /auth/login` directly (no new identity system in `agentic-ai`), holds the
resulting access token in Gradio session state, and uses it for both the Direct RAG and Agentic
RAG tabs so a logged-in visitor genuinely sees their own documents in both.

## Acceptance Criteria

- [x] A login component (email/password fields, matching what the RAG platform's own `/auth/login`
      expects) — an `Accordion` above the two tabs, collapsed by default, so a casual demo visitor
      isn't forced to look at it
- [x] Successful login stores the access token in `gr.State` (per-browser-session, not global)
- [x] Both `run_direct_query` and `run_agentic_query` take the logged-in token and use it (the
      former via `_get_retrieval_client(user_token)`, the latter via `get_graph(user_token)`)
- [x] No login = today's behavior unchanged — both functions default `user_token` to `None`
- [x] A clear, non-crashing message when a token is invalid/expired: `run_direct_query` catches
      `RagPlatformAuthError` (or a 401 surfaced as a retrieval error) and returns "please log in
      again" instead of propagating a stack trace to the UI

## Notes

Deliberately no "remember me" / persistent session beyond the browser tab — this is a demo UI, not
a product with real session management requirements.
