# AGT-005 — Decide and Provision Hosting for the Agentic-AI Service

Status: Done
Depends On: AGT-004
Category: Improvement

## Description

Once this project no longer needs to run Ollama itself (`AGT-004`), its own service is a thin
FastAPI app plus a lightweight MCP subprocess — small enough to plausibly co-host with the
existing RAG platform, but that VM is already resource-constrained (see `AGT-004`'s description
and `ERP-047` in the sibling repo). Two real options, not yet decided:

**Option A — co-host on `rag-platform-host`** (the existing GCP e2-micro VM)
- Zero new cloud resources to provision or track
- Risk: adds load to an already-thin (958MB RAM) host already running one service; a second
  always-on process competing for that headroom is exactly the kind of thing that caused
  `ERP-047`'s real outage
- Needs: a new systemd service, a new Caddy route (path-based, e.g. `/agentic/*`, or a second
  sslip.io-style hostname), a new firewall rule if using a distinct port

**Option B — Cloud Run** (same pattern already proven in this portfolio for
`enterprise-rag-platform`'s docling service)
- Isolated from the RAG platform's own resource budget entirely
- Matches `docs/architecture.md`'s own stated principle: "keep the always-on host thin; offload
  anything CPU/memory-heavy to serverless compute"
- Free within Cloud Run's tier at this project's traffic scale (same free-tier allowance docling
  already uses, per `gcp-deployment-tracker.md`)
- HTTPS included automatically, no Caddy/sslip.io setup needed
- New resource to track and add to the portfolio's teardown checklist
- Needs verification: Cloud Run's request/response model supports this app's SSE streaming
  endpoint and its MCP-subprocess-spawning pattern (both should work — Cloud Run supports
  streaming HTTP responses and arbitrary subprocess spawning inside the container — but not yet
  confirmed live for this specific app)

## Acceptance Criteria

## Notes

**Resolved (2026-10-01):** Option B, Cloud Run — decided by the project owner for its zero
free-tier cost and isolation from `rag-platform-host`'s already-thin resource budget. Deployed via
`--source .` Dockerfile build; live at
`https://agentic-ai-167676028188.us-central1.run.app` (512Mi/1cpu, timeout=300s, concurrency=10,
min-instances=0, max-instances=3). `POST /query` verified end-to-end against the live
`enterprise-rag-platform` deployment and OpenRouter (`AGT-004`), including discovering and fixing
a real auth-contract mismatch (`ERP-116` cookie+CSRF hardening, not present in local dev) along the
way. Tracker entry recorded in `gcp-deployment-tracker.md` under "`agentic-ai` — Cloud Run
Deployment (2026-10-01, AGT-005/007)".
