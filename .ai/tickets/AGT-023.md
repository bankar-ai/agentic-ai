# AGT-023 — Rename Vercel Project to Match `enterprise-rag-platform`'s Convention

Status: Done
Depends On: None
Category: Improvement

## Description

`agentic-ai`'s Vercel project still has its auto-generated subdomain
(`agentic-ai-psi-mauve.vercel.app`). `enterprise-rag-platform` hit the exact same cosmetic issue
and fixed it the same way (`ERP-057`): renamed the Vercel project to a readable, org-prefixed
name (`bankar-ai-self-hosted-rag-platform.vercel.app`). Do the same here for consistency across
the portfolio.

**Known gotcha from ERP-057, applies identically here:** the backend's CORS allowlist is an exact
string match on Origin — renaming the Vercel project without updating `CORS_ALLOWED_ORIGINS` on
Cloud Run breaks login silently (browser blocks every cross-origin request, no server-side error
to find). Both must change together.

## Acceptance Criteria

- [x] Readable URL live: `bankar-ai-agentic-rag-orchestrator.vercel.app`
- [x] `CORS_ALLOWED_ORIGINS` on the `agentic-ai` Cloud Run service updated to accept the new origin
- [x] Live-verified: `200 OK`, no SSO redirect, serving the current build
- [x] `gcp-deployment-tracker.md` updated

## Resolution (2026-10-04)

First attempt (`vercel alias set` creating `bankar-ai-agentic-ai.vercel.app`, mirroring
`enterprise-rag-platform`'s `ERP-057`) hit Vercel's SSO deployment protection — that alias wasn't
exempted the way the project's own canonical domain was, for reasons not fully root-caused (both
projects reported identical `ssoProtection` settings). The actual fix for a project on Vercel's
free tier turns out to be different: the **project owner connected the GitHub repo directly**
(previously only CLI `vercel deploy --prod` worked — git auto-connect had failed during `AGT-017`)
and added `bankar-ai-agentic-rag-orchestrator.vercel.app` as a real project **Domain** (not a bare
CLI alias) marked Production. A genuine Production domain is exempted from SSO protection
automatically — confirmed live via `curl -sI`: `200 OK`, no redirect, serving the current bundle
(`index-CYYS_rBe.js`, matching the latest deploy).

**Caught and fixed along the way**: connecting the GitHub repo left the project's **Root
Directory** setting blank (repo root) — correct for the old CLI-only deploys (which built from
inside `frontend/` directly, bypassing this setting entirely) but wrong for Git-triggered builds,
which would have failed finding no `package.json` at the repo root. Project owner set it to
`frontend` before any Git-triggered build actually ran (confirmed via `vercel ls` — only the 2
pre-existing CLI deploys exist, no failed Git build to clean up).

Net effect: `agentic-ai-psi-mauve.vercel.app` (original) and
`bankar-ai-agentic-rag-orchestrator.vercel.app` (new, readable) both work. GitHub is now connected
for auto-deploy on push to `main` (the repo's default branch, matching this project's "`main` =
what's deployed" convention everywhere else).
