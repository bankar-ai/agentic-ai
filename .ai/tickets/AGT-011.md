# AGT-011 — Evaluation Milestone: Langfuse Datasets/Scores

Status: Done
Depends On: None
Category: Improvement

## Description

The spec's Testing section calls for "a small hand-built eval set (Q&A pairs with known-correct
answers and known-should-refuse cases) to regression-test groundedness and refusal behavior over
time — feeds into the Langfuse-tracked evaluation loop." The current implementation covers the
*mechanism* (every agent step is traced via `app/core/tracing.py`, with a no-op fallback) but not
yet an actual curated eval dataset or scoring against it in Langfuse.

## Acceptance Criteria

- [ ] A small, hand-built Q&A eval set (known-correct answers + known-should-refuse cases, per the
      spec) — likely overlapping with whatever content `AGT-006` ingests for the live demo, so a
      consistent corpus backs both
- [ ] Eval set runnable against the live graph, with results scored/logged to Langfuse (dataset +
      score API, not just per-query tracing)
- [ ] A repeatable way to re-run the eval set as a regression check (script or test, not a one-off
      manual exercise)

## Notes

**Soft dependency on `enterprise-rag-platform`'s `ERP-112`** (Langfuse integration, currently
Backlog there) — not a hard blocker: this project's own Langfuse tracer already degrades
gracefully to a no-op without credentials, and a Langfuse Cloud account/project can be stood up
independently if `ERP-112` is still pending when this ticket is picked up. See
`.ai/memory/decisions-in-progress.md`'s "ERP-112 sequencing" entry.

**Resolved (2026-10-04):** `scripts/run_eval.py`, verified against the installed `langfuse` SDK
(4.16.0) directly rather than assumed — `Langfuse.run_experiment()` + `langfuse.Evaluation` is
its current API (the old `Langfuse.score()`/dataset-run pattern from the original spec text no
longer exists in this version). 4 hand-built cases: two KB-grounded known-correct, one
web-fallback known-correct, one known-should-refuse. Scores to Langfuse when
`LANGFUSE_PUBLIC_KEY`/`SECRET_KEY` are configured, otherwise runs and reports the same way with
`tracing_enabled=False` (no remote calls) — mirrors `app/core/tracing.py`'s own
no-op-when-unconfigured stance, so this is runnable without requiring a Langfuse account at all.

**Why KB retrieval is a fixture, not a live `enterprise-rag-platform` account:** superseded by
`AGT-006` — there is no shared/anonymous demo account to ingest eval content under anymore, so
the eval set can't assume one exists on whatever account someone runs it with. KB-route cases use
the same small fixture (`tests/fixtures/sample_kb.py`) the integration tests already use;
web-fallback and refuse cases exercise the real Gatekeeper/Writer/Verifier reasoning and a real
live web search, same as production.

**A genuine finding from running this live, not a tooling bug:** the first version of the
refuse-case query ("...colorless green ideas furiously sleep purple") was built as a nonsense
string, but it happens to closely paraphrase Chomsky's famous example sentence from linguistics —
the system correctly recognized this, researched it, and gave a well-grounded answer *about* that
sentence rather than refusing. That's the *correct* behavior, not a bug; the eval case itself was
the problem (an accidentally-answerable "nonsense" query), fixed by swapping to a question with no
real-world referent at all. All 4 cases pass after that fix.
