# AGT-025 — Show the User's Own Ingested Documents

Status: Done
Depends On: None
Category: Feature

## Description

A user has no way to see what's actually in their knowledge base before asking a question — they
have to guess, or get surprised by a refusal. `enterprise-rag-platform` already exposes
`GET /documents` (ERP-103, returns the caller's successfully ingested documents, paginated,
cookie+CSRF authenticated same as `/retrieval/query`) — this is a proxy of an existing capability,
not new backend work on that platform's side.

## Acceptance Criteria

- [x] New method on a small `RagPlatformDocumentsClient` (`app/rag_client/documents.py`),
      mirroring `RagPlatformRetrievalClient`'s auth pattern exactly (Cookie + X-CSRF-Token
      headers, refresh-once-on-401/403, `RagPlatformRetrievalError`-style error type)
- [x] New `GET /documents` on `agentic-ai`'s own API (`app/api/router.py`), requiring the same
      `Authorization`/`X-RAG-CSRF-Token` headers as `/query`, returning the caller's documents
      (filename, ingested date)
- [x] Frontend: a documents list visible from the query page (collapsible panel), showing
      filename + ingested date, with a clear empty-state message since there is no upload
      capability here
- [x] Tests: client auth/refresh behavior (mocked), endpoint auth requirement (6 new tests)
- [x] Live-verified against the real RAG platform

## Resolution (2026-10-04)

Deployed as revision `agentic-ai-00021-pmn`. Live-verified with a real logged-in session:
`GET /documents` returned `200 {"documents":[],"has_more":false}` (empty because this test
account has no ingested content, same known state noted elsewhere in this project — not an
error). Also confirmed `GET /documents` with no auth headers returns `401`, matching `/query`'s
own contract. Frontend panel confirmed present in the deployed JS bundle ("Your documents"
string); not visually clicked through in a real browser this session.
