# AGT-010 — Writer/Verifier Structured-Output Reliability with Local Models

Status: Backlog
Depends On: None
Category: Lapse

## Description

Small local models (`qwen3:8b`, `granite4:tiny-h`, both confirmed tool-call-capable) sometimes
reply in plain prose instead of making the required structured tool call at the Writer and
Verifier steps — confirmed via live testing (2026-09-30) to be genuine model-reliability
flakiness, not a code defect; the model consistently produces *correct, well-cited content*, just
in the wrong format. Partially mitigated already (`917e8ef`): stronger system prompts + raised
PydanticAI retry budget (1 → 3). Format-failure rate dropped from 4/4 (100%) to roughly 1/3 across
further live attempts — real, but incomplete.

`model_settings=ModelSettings(tool_choice="required")` was tried as a stronger fix and reverted:
PydanticAI raises `UserError` for agents with only `output_type` and no function tools (forcing
`tool_choice` would exclude the output tool itself) — that mechanism doesn't apply to this
agent shape. See the code comments in `app/agents/writer.py`/`verifier.py` for the full note.

## Notes

Category is **Lapse** — the agents work exactly as designed; the design didn't originally account
for how unreliable small local models are at consistently honoring structured-output tool calls.
Not a blocking Bug: the system's own guardrails (bounded retries, then refuse rather than
fabricate) already handle this failure mode safely — a flaky Writer/Verifier produces a *refusal*,
never a wrong or ungrounded answer. This ticket is about demo reliability (how often a live query
actually succeeds), not correctness.
